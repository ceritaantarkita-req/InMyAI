## Fix #2 — Context retrieval excerpt bug (backend)

**TDD cycle:**
1. **RED** — tambah test di `services/api/tests/test_core.py`:
   `test_build_context_locates_relevant_excerpt()` — bikin file yang relevant content-nya BUKAN di awal (±3000 char padding di depan, baru kalimat kunci), index, panggil `build_context()`, assert excerpt **mengandung** token relevan (bukan cuma awal file). Verifikasi test gagal dengan pytest.
2. **GREEN** — di `services.py`:
   - Tambah pure helper `_locate_excerpt(content: str, query: str) -> int`: coba exact phrase dulu, fallback ke first matching token dari query, terakhir return 0.
   - Ganti `index = max(content.lower().find(query.lower()), 0)` jadi `index = _locate_excerpt(content, query)`.
   - Verifikasi pass.
3. **REFACTOR** — bersihkan redundant `max(0, index-500)` jadi `index-500` (index selalu ≥0).

Run: `python -m pytest services/api/tests/test_core.py::test_build_context_locates_relevant_excerpt -q`

## Fix #1 — Tool dispatch dari chat (OCR via path parse)
**Bug** (`services/api/app/main.py:212-221`): router bisa return `provider='local-tool'` (engine tesseract/diff/image-router) tapi `/api/chat` cuma branch `ollama` vs `else: Mock`. Maka "ocr invoice ini" di-chat → routed ke tesseract → dijalankan oleh Mock. Janji routing palsu.

**Scope**: implementasi eksekusi nyata hanya untuk **OCR** (single file + deterministic tool). `diff` & `image` dapat guidance message explicit (lebih honest dari silent mock) — implementasi penuhnya tunda ke diskusi chat UX terpisah.

**TDD cycle:**
1. **RED** — tambah test di `services/api/tests/test_core.py`:
   - `test_extract_file_reference_finds_path()` — pure test helper: `'please OCR invoice.png'` → `'invoice.png'`; `'scan src/scan.pdf'` → `'src/scan.pdf'`; `'no file here'` → `None`.
   - `test_chat_dispatches_ocr_when_path_present()` — POST `/api/chat` dengan message `'ocr invoice.png'` (file invoice.png sudah ada dari setup_module), assert response `provider == 'local-tool'` dan `answer` mengandung teks OCR (`'INVOICE'`).
   - `test_chat_ocr_without_path_returns_guidance()` — message `'ocr this'` (no path) → provider `'local-tool'`, answer mengandung kata guidance (mis. `'Studio'` / `'file'`).
   - `test_chat_ocr_missing_file_is_graceful()` — message `'ocr doesnotexist.png'` → tidak 500, answer bilang file tidak ditemukan.
   - `test_chat_diff_task_returns_guidance_not_mock()` — message `'diff these files'` → provider `'local-tool'` (bukan `'mock'`), answer arahkan ke tab Files.
   Verifikasi semua gagal.
2. **GREEN**:
   - Di `services/api/app/services.py`: tambah pure helper `extract_file_reference(message: str) -> str | None` — regex `[\w\-./\\]+\.(?:png|jpe?g|webp|bmp|tiff|pdf)` case-insensitive, return first match atau None.
   - Di `main.py` `/api/chat` handler: sebelum branch ollama/mock, cek `if decision.provider == 'local-tool':`
     - `task == 'ocr'`: parse path via `extract_file_reference`. Kalau ada & file valid (safe_join + exists) → `services.run_ocr(...)` → result text jadi `ProviderResult(text=..., model='tesseract', provider='local-tool')`. Kalau path ada tapi file gak ada → guidance "file tidak ditemukan: X". Kalau gak ada path → guidance "sebut nama file PDF/gambar, mis. 'ocr invoice.png', atau buka tab Studio".
     - `task == 'diff'` → guidance "bandingkan file di tab Files via proposal diff".
     - `task == 'image'` → guidance "generate gambar di tab Studio".
     - Set `result` & skip ollama/mock.
   - Verifikasi semua test pass.
3. **REFACTOR** — extract dispatch ke helper `run_local_tool_decision(decision, message, project_id) -> ProviderResult` kalau handler jadi crowded.

Run: `python -m pytest services/api/tests/test_core.py -q`
